# 네트워크 보안요구사항 명세 (학습 1-1)

## 절차

1. **법·인증 기준을 확인한다.** (pp.8-12) 정보통신망법의 네트워크 보안 기준, 개인정보보호법(내부 관리계획,
   접근 통제·권한 제한), ISMS-P의 네트워크 관련 기준. `policy_docs`.
2. **요구사항을 도출하고 검토한다.** (p.16) 자산 식별 → 자산별 보안 위협 → 보호 우선순위(기밀성·무결성·가용성).
3. **요구사항을 명세한다.** (p.17)
4. **명세서를 승인받아 확정한다.** (p.19) 누가(정보보호 책임자 등), 어떤 문서(요구사항 명세서)로 승인하는지 적는다.
   랩: `approval_request`(명세서를 변경 요청서처럼 change_prepare kind=network-design로 올린다).

## 자산 식별표 (시험 문항1 유형)

| 자산 | 분류 | 담당 | 보안 위협 | 우선순위(CIA) |
|---|---|---|---|---|
| 업무·DB 서버 | 서버 | | 비인가 접근, 데이터 유출·변조 | 기밀성·무결성 |
| 방화벽·IPS | 네트워크 보안 | | 정책 오설정, 장애, 우회 | 가용성·무결성 |
| 무선 AP | 네트워크 장비 | | 비인가 접속, 도청 | 기밀성 |
| 관리자 워크스테이션 | 단말 | | 악성코드 감염 후 관리 권한 탈취 | 기밀성·무결성 |
| 백업·로그 서버 | 서버·보안 분석 | | 삭제·변조, 수집 중단 | 무결성·가용성 |

## 명세 문장 예

- 내부망의 개인정보는 접근 통제와 암호화로 보호한다.
- 외부와 접하는 서버는 DMZ에 분리하고 화이트리스트(최소 허용) 정책으로 서비스 포트만 허용한다.
- 모든 보안 장비의 로그는 중앙 로그 서버(SIEM)로 전송·보관한다.
