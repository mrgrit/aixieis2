# 업데이트 계획 수립 (학습 4-1)

## 패치 관리 절차 (p.54, [그림 4-2])

1. 신규 보안 업데이트 정보를 수집한다.
2. 네트워크 자산 목록을 작성한다(`asset_inventory`).
3. 솔루션 목록과 벤더별 패치 방법을 정리한다.
4. 최신 공개 취약점과 패치 내용을 확인·검토한다.
5. 솔루션 운영환경을 분석한다(이중화 여부, 세션 단절 영향, 업무 시간).
6. 패치 적용 계획을 세운다.
7. 패치를 시험한다(테스트·스테이징 장비).
8. 패치를 적용한다.
9. 모니터링한다.

## 중요도·시급성 판단

| 업데이트 | 보는 것 |
|---|---|
| 탐지 룰(고위험 CVE 대응, 서비스 영향 없음) | 시급. 영향이 없으므로 가장 먼저, 업무 시간에도 가능 |
| 엔진(악성코드 변종 대응, 실패 시 처리 지연) | 중요. 실패 시 영향이 크므로 시험 후 점검 시간에 |
| OS 패치(안정성·VPN 오류 수정, 세션 단절 수분) | 계획 필요. 세션 단절 → 점검 시간 공지 후 |

## 적용 전 준비 (시험 문항4 과제1)

사전 백업(설정·이미지), 점검 시간 선정과 공지, 롤백 절차, 테스트 환경 사전 시험, 변경 관리 문서.
이 다섯 가지가 `change_prepare`의 test_plan·rollback·reason에 들어가야 한다.
