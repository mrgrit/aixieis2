# 네트워크 보안 요구사항 분석 (학습 1-1)

## 절차

1. **규정·지침에서 네트워크 보안 요구사항을 뽑는다.** (p.4) 정보보호 제도·정책·지침에서 네트워크
   운영에 요구되는 항목을 찾고, 적용할 통제 수준을 정한다. 랩: `policy_docs`.
   - 흔한 요구사항 예: 접근통제(최소 허용), 분리망 구조, 로그 보존, 암호화 통신(VPN·터널),
     정책 변경 이력 관리, 장비 관리자 인증.
2. **담당자 인터뷰로 현황을 파악한다.** (p.4) 랩: `worker_directory`로 구축 담당(`nw-sec-build`)을
   확인하고 필요하면 질의를 남긴다.
3. **보호 대상을 도출한다.** (p.4) 랩: `asset_inventory`(중요도·존).
4. **보호 대상별 취약점과 위협을 분석한다.** (p.5) 네트워크 기반 취약점(전체 망, 방화벽 설정 오류)과
   호스트 기반 취약점(특정 호스트)을 구분한다(<표 1-1>).
5. **위협에 대응할 보안 요구사항을 도출한다.** (p.6) 장비 보안 기능 필수 점검표(<표 1-2>) 예:
   기본 비밀번호 변경, 9자리 이상 조합 비밀번호, 인증 실패 5회 이하 시 5분 이상 접속 제한, 비밀번호 마스킹.
6. **구성도를 모으고 망별·운용 현황별로 현황을 확인한다.** (p.8) 랩: `network_topology`, `fw_rules`, `ids_rules`.
7. **보안 솔루션 현황을 파악한다.** (p.8) 솔루션별 역할·위치·정책 수·마지막 업데이트일.

## 산출물

| 요구사항 | 근거 규정 | 현재 상태(도구·근거) | 충족 | 미충족 사유 |
|---|---|---|---|---|
