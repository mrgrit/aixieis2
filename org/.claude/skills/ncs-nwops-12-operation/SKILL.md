# 네트워크 보안 솔루션 운영 (학습 1-2)

## 운영 절차 점검 (pp.14-16)

1. 요구사항에 맞게 보안 정책을 점검·개선하고, 새 정책의 통제·점검 항목이 운영 절차에 들어갔는지 확인한다.
2. 솔루션 도입 지침: 신규 도입·개선 계획, 도입 기준, 도입 후 **인수 테스트** 여부를 확인한다.
3. 장애 관리 절차와 산출물(서식·내용)을 점검한다.
4. 원격 운영 관리 절차: 관리자 접근을 어디서 어떻게 허용하는지, 운영 원칙이 적정한지 점검한다.
5. 공개 서버 등 위협이 큰 자산에 대한 운영 절차를 따로 점검한다.
6. 솔루션 자체의 취약점 관리(패치·불필요 서비스)를 확인한다.
7. 운영 주체가 불분명한 솔루션은 담당을 정하고, 점검으로 알려진 취약점을 제거한다. (p.16)

## 정책 신청 검토 (일상 운영)

방화벽·IPS 정책 신청을 받으면:

1. 신청 내용(출발지, 목적지, 포트·프로토콜, 기간, 업무 사유)이 다 있는지 본다. 빠지면 반려한다.
2. `fw_rules`로 현재 정책과 순서를 읽고, **처음 일치하는 규칙이 적용**된다는 전제로 신청 규칙이
   어디에 들어가야 하는지 정한다. 위에 더 넓은 허용·차단 규칙이 있으면 신청 규칙은 동작하지 않는다.
3. 과도 허용(any 출발지, 넓은 포트 범위, 기간 없는 임시 허용)을 피하고 최소 범위로 바꿔 제안한다.
4. 변경은 `change_prepare`(kind=fw 또는 ids)로 준비한다. 근거(evidence_refs), 시험 계획(test_plan:
   허용돼야 할 연결과 막혀야 할 연결), 원복 방법(rollback)을 반드시 적는다.
5. `approval_request` → 승인 후 `change_apply` → 적용 후 시험 계획대로 확인하고 결과를 보고한다.
