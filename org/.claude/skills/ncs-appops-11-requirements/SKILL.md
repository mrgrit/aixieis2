# 애플리케이션 보안 요구사항 분석 (학습 1-1)

## 절차

1. **구조와 솔루션 현황을 파악한다.** (pp.4-6) 아키텍처 정의서·자산 관리 대장으로 애플리케이션을
   망별·용도별로 나누고, 보안 솔루션 현황을 확인한다. 랩: `asset_inventory`, `waf_config`.
2. **규정에서 요구사항을 찾는다.** (p.6) 관련 법률(정보통신망법, 개인정보 보호법 등)과 내부 규정의
   준거 사항을 찾는다. 랩: `policy_docs`.
3. **담당자 인터뷰로 요구사항을 보완한다.** (p.7) 인터뷰 계획 → 인터뷰 → 결과서. 랩: 필요한 질문을
   담당에게 `handoff_request`로 남긴다.
4. **보안 요구사항 정의서를 쓴다.** (p.8) 요구사항을 구분해 정리한다.

## 요구사항 항목 (시험 문항1 유형)

| 항목 | 정의서에 적을 내용 |
|---|---|
| 인증·인가 | 로그인 실패 제한, 세션 관리, 권한별 접근 통제 |
| 암호화 | 전송 구간(HTTPS), 비밀번호 단방향 암호화, 중요 정보 저장 암호화 |
| 로그·SIEM 연동 | 접근·인증·에러 로그 수집과 SIEM 전송, 보존 기간 |
| 입력값 검증 | 서버 측 검증, WAF 입력 필터 규칙 |
| 에러 처리·정보 노출 방지 | 스택 트레이스·DB 오류 메시지를 사용자에게 보이지 않음 |
| 패치·업데이트 | 솔루션·애플리케이션 패치 주기와 절차 |
| 취약점 점검·개선 | 정기 점검 주기, 조치 기한 |
