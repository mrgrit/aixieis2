# 보안로그 분석 (학습 1-2)

목표: 보안로그에서 오탐 여부를 판정하고, 공격자 IP·공격 기법을 추출하고, 보안장비가 생성한 패킷을 확인한다.

## 절차

1. **로그 항목의 뜻을 확인한다.** (p.19) 각 필드(탐지명, 출발지/목적지, 프로토콜, PPS, Action,
   응답 코드 등)가 무엇을 뜻하는지 정리하고, 기본정보를 어떤 순서로 볼지 정한다.
2. **오탐 유무를 확인한다.** (p.21)
   1. 해당 로그를 만든 탐지 규칙(룰 그룹, 실제 규칙, 적용 패턴, 패턴 세부 값=임계치)을 확인한다.
      랩: IPS 규칙은 `ids_rules`, WAF는 `waf_events`의 rule_id.
   2. 규칙과 실제 탐지 내역을 비교한다.
   3. 비교 결과로 판정한다.

   | 비교 | 판정 |
   |---|---|
   | 탐지 내역이 패턴 세부 값(임계치)을 넘는다 (예: 20,000/초 > 200/초) | 정탐 |
   | 탐지 내역이 패턴 세부 값에 못 미치는데 경보가 났다 | 오탐 (규칙 점검 필요) |
   | 페이로드가 규칙의 공격 패턴과 일치하고 대상이 실제 서비스다 | 정탐 |
   | 규칙이나 원본 로그를 확인할 수 없다 | 판정 보류 (확인 불가 사유를 적는다) |

3. **공격자 IP를 추출한다.** (p.22) IP가 들어 있는 로그 항목을 정하고, 추출한 뒤 **적정성**을
   검사한다(사설 대역·NAT·내부 점검 서버·위조 가능성).
4. **공격 기법을 추출한다.** (p.23) 장비가 판정한 기법을 확인하고, 그 **공격 원리**를 조사하고,
   분석자가 유추한 기법과 비교해 적정성을 평가한다. 예) TCP SYN Flooding: 3-way handshake의
   SYN만 대량으로 보내 서버의 연결 대기열(backlog)을 채워 정상 연결을 받지 못하게 한다.
5. **패킷을 확인·보존한다.** (p.23) 장비 매뉴얼의 패킷 저장 방법대로 저장소를 만들어 저장한다.
   파일 이름에 사건 번호·공격 방식·사건 일시를 넣는다(p.24 tip). 랩: 저장은 `ticket_create`에
   보존 요청으로 남긴다(분석가는 장비에 직접 쓰지 않는다).

## 결과 확인

탐지와 차단은 다르다. Action과 응답 코드를 함께 본다.

| 관찰 | 해석 |
|---|---|
| Action이 차단, 응답 403 등 | 공격 시도 — 막힘 |
| Action이 Alert·Log Only, 응답 200 | 탐지만 됨 — 공격이 서버까지 도달, 성공 가능 |
| 응답 200·302 뒤 인증 후 페이지 접근, 큰 응답 | 성공 징후 |

## 산출물

판정(정탐/오탐/보류)과 비교 근거, 공격자 IP(적정성 메모 포함), 공격 기법·원리, 보존한 패킷 목록.
