# 네트워크 보안 설계 (학습 1-2)

## 절차

1. **서버 네트워크 보안 설계** (p.24): 외부 공개 서버는 DMZ, 핵심 서버는 내부, 구간 경계에 방화벽·IPS.
2. **사용자 단말 네트워크 보안 설계** (p.27): 단말망 분리, 단말에서 서버망 접근 통제.
3. **보안 자산 정보 관리 체계 설계** (p.32).
4. **네트워크 보안관제 체계 설계** (p.33): 장비 로그를 SIEM으로.
5. **보안성 승인 절차 설계** (p.33): 구성 변경 시 승인·변경관리.

## 구간별 접근제어 정책표 (시험 문항2 유형)

정책은 **번호 순으로 적용되고 처음 일치한 정책이 쓰인다**. 그래서 구체적인 허용을 위에, 마지막에 전체 거부를 둔다.

| 번호 | 출발지 | 목적지 | 프로토콜/포트 | 동작 | 목적 |
|---|---|---|---|---|---|
| 1 | 외부(Any) | DMZ 웹서버 | TCP 80, 443 | 허용 | 웹 서비스 제공 |
| 2 | DMZ 웹서버 | 내부 DB 서버(지정 IP) | TCP DB 포트 | 허용 | 웹–DB 연동 |
| 3 | 내부 관리자 PC(특정 IP) | 개발·운영 서버 | TCP 22 | 허용 | 관리 접속 |
| 4 | 내부 장비, DMZ | SIEM | syslog(UDP 514) 등 | 허용 | 로그 중앙 수집 |
| 5 | Any | Any | Any | 거부 | 명시 허용 외 전부 차단(역방향 포함) |

주의: 2025 내부평가 문항2 정책표에는 syslog가 UDP/513으로 적혀 있다. syslog 표준 포트는 UDP 514이고,
513은 rlogin/rwho 계열이다. 출제 의도를 확인할 것.

## KT66 대응

KT66 존은 ext(L0) → pipe → dmz(L2) → int(L3), app(L3), ot(L3·격리)이며, 존 사이 경로는 fw·ips·web(WAF)뿐이다
(`network_topology`). 설계 산출물은 KT66 존 이름으로 정책표를 쓴다.
