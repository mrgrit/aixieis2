# 제로 트러스트 관점의 구간 설계 (확장)

NCS 1-2의 설계는 외부·DMZ·내부의 **경계** 중심이다. NIST SP 800-207은 네트워크 위치나 자산 소유만으로
암묵적 신뢰를 주지 말고, 자원(자산·서비스·워크플로·계정) 단위로 보호하며, 세션을 열기 전에 주체와 장치의
인증·인가를 따로 하라고 한다.

## 점검 질문

| 질문 | 경계 중심 설계에서 흔한 답 | 바꿀 방향 |
|---|---|---|
| 내부망 PC가 서버 관리 포트에 닿는가 | 내부라서 허용 | 관리 포트는 관리 단말·인증 후에만 |
| 서버끼리(동서 트래픽) 막혀 있는가 | 같은 존이면 전부 허용 | 필요한 서비스 포트만 허용 |
| 인증 없이 열리는 내부 관리 화면이 있는가 | 있음 | 인증·로그 필수 |
| 정책 결정의 근거가 위치(IP)뿐인가 | 예 | 사용자·장치 상태를 함께 |

KT66에서 `mgmt`는 별도 망이 아니라 **권한 경계**로만 정의돼 있다(`network_topology`의 logical_zone). 이것이
제로 트러스트 관점의 출발점이 된다: 관리 도구가 dmz에 있지만 권한으로 분리돼 있다.
