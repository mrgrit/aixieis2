# 복구 및 문서화 (학습 3-2)

## 절차

1. **침해 관련 데이터를 수집한다.** (p.45) 네트워크 기반 증거(방화벽·IPS 로그, 세션, 설정 파일)를
   모으고 원본을 보존한다. 분석 단계에서 무엇이 어디서 왔는지 기록한다.
2. **원인을 조사한다.** (p.46) 수집 자료로 취약 원인(설정 미흡, 접근통제 누락 등)을 찾는다. 공격 판정은
   관제(`soc-analyst`) 결과를 근거로 쓰고, 운영 담당은 장비 측 원인에 집중한다.
3. **복구한다.** 추가 피해를 막고 재발을 방지한다(p.47): 위험 우선순위 식별, 원인과 복원 조치 기술,
   근원 원인 파악, 침해 장비 복구, 밝혀진 취약점 조치(IDS, 접근통제, 방화벽).
4. **정상화를 확인한다.** 항목마다 '어떻게 확인할지'를 적고 확인한다.

   | 확인 항목 | 확인 방법 |
   |---|---|
   | 관리 포트 응답 지연 | 관리망에서 응답 시간 측정, 평소 값과 비교 |
   | 같은 공격 패턴 재발 | IDS/IPS 로그에서 같은 시그니처·출발지 검색 |
   | ACL 정상 적용 | 설정 조회로 규칙 존재·순서 확인, 차단돼야 할 연결 시험 |
   | 로그 전송 정상 | 수집 서버에 최근 로그가 들어오는지 확인 |

5. **보고서를 쓴다.** (<표 3-5>) 1. 보안 위협 발생 개요(시나리오 요약) 2. 네트워크 보안 취약점 분석
   (취약 원인) 3. 위협 영향도 분석 4. 조치 사항(차단·복구 내역).
