# 복구 및 문서화 (학습 3-2)

## 절차

1. **원인을 제거한다.** (p.56) 차단 후 유닉스·리눅스(계정, 프로세스, 예약 작업, 시작 스크립트, 웹셸 등)와
   윈도우 각각에서 침해 원인을 확인하고 제거한다. 제거 전에 증거를 남긴다.
2. **포렌식 절차를 수행한다.** (p.58) 초기 대응 → 대응 전략 수립 → 사고 조사(법적 증거 수집·분석) → 포렌식
   조사 보고서.
3. **복구한다.** (p.59) DR 솔루션의 복제 백업 데이터로 복구한다.
4. **통제 회복을 확인한다.** (p.59) 관리적·기술적·물리적으로 모든 업무 환경의 제어가 회복됐는지.
5. **기록하고 보고한다.** (p.60) 처리·복구 행위를 절차대로 기록하고, 결과 보고서(<표 3-2>)로 원인 분석·결과를
   보고하고, 사고 정보를 공유하고, 재발방지 대책을 세우고 요청한다.

## 침해 사고 분석 절차 7단계

사고 전 준비 → 사고 탐지 → 초기 대응 → 대응 전략 체계화 → 사고 조사 → 보고서 작성 → 복구·해결.
전체 조정은 `cert-coordinator`가 맡고, 시스템 운영 담당은 서버의 원인 제거·복구·확인을 맡는다.
