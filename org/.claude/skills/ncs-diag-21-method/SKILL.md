# 취약점 진단 방법 파악 (학습 2-1)

## 대상별 진단 방법

| 대상 | 진단 대상 파악 | 취약점 항목 | 진단 방법 |
|---|---|---|---|
| 서버 (p.37) | 진단 대상 서버 내역(<표 2-1>) | 유닉스(<표 2-2>), 윈도(<표 2-3>) | 계정 관리, 응용 보안 설정, 네트워크 서비스, 시스템 환경·파일·디렉터리, 로그·패치 설정 확인 |
| 네트워크 (p.40) | 구성도, 장비 목록(<표 2-4>) | 점검 항목(<표 2-5>) | 진단 방법(<표 2-6>): Ping·TCP/UDP 포트 스캔, SNMP, 배너 |
| 애플리케이션 (p.42) | 애플리케이션 서버(<표 2-7>) | 취약 내역(<표 2-8>) | 소스·동작 점검 |
| 데이터베이스 (p.45) | DB 목록(<표 2-9>) | 취약점 내역(<표 2-10>) | 기본 계정 비밀번호·정책, DBA 권한 최소화, 원격 접근 제한, 보안 패치 |

## 방법 고르기

| 대상 | 목적 | 방법 |
|---|---|---|
| 정보보호 정책(관리적) | 정책 인지·승인 여부 | 인터뷰(면담) — 체크리스트와 질문서 |
| 네트워크 장비 | 열린 포트·서비스 식별 | 기술적 진단(스캐닝) — Ping, TCP/UDP 스캔 |
| 유닉스 서버 | 내부 설정 정밀 점검 | 기술적 진단(로컬 점검) — 점검 스크립트, Manager-Agent 구조 |

랩에서는 `host_config`, `host_accounts`, `package_inventory`, `fw_rules`, `waf_config`, `network_topology`가
로컬 점검·설정 조회에 해당한다. 진단 담당은 조회만 하고 조치하지 않는다.
