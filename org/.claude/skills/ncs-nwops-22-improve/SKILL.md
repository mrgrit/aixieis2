# 운영 개선 (학습 2-2)

## 절차

1. **솔루션의 취약점을 진단한다.** (p.30) 진단 목적은 노출 수준 점검, TCP/IP 주요 취약점 식별,
   호스트 보안 개선, 정책 적합성 확인, 기술적 대책 수립이다. (p.32)
2. **점검 위치를 정한다.** (p.32) 네트워크 구조 식별 → 서비스 스캐닝 → 네트워크 취약점 점검 → 시스템 취약점 점검.
3. **개선안을 검증한다.** 개선안마다 검증 계획을 먼저 쓰고(무엇을, 어떻게, 통과 기준) 결과로 판단한다.
   예) 정책 재정비 → 재정비 전후로 허용·차단돼야 할 연결 목록을 시험해 같은 결과가 나오는지.
4. **최종 개선 조치를 한다.** 검증을 통과한 개선안만 `change_prepare` → 승인 → `change_apply`로 적용한다.
5. **정기 점검 절차로 남긴다.** 다음 점검 주기, 점검 항목, 담당을 운영 문서(티켓)로 남긴다.
