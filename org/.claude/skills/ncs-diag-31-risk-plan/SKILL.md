# 취약점 위험 대응 계획 수립 (학습 3-1)

## 위험 처리 유형

| 유형 | 뜻 | 예 |
|---|---|---|
| 위험 감소 | 대책을 적용해 위험을 줄인다 | 접근 통제, 패치, 암호화 |
| 위험 회피 | 위험을 만드는 원인(서비스·기능)을 없앤다 | 외부 노출 관리자 페이지 제거 |
| 위험 전가 | 보험·외주 계약 등으로 손실을 넘긴다 | 사이버 보험 |
| 위험 수용 | 비용이 위험보다 크거나 영향이 작아 받아들인다 | 폐기 예정 폐쇄망 서버 |

## 조치 기간 산정 기준 (<표 3-7>, p.72)

| 기간 | 기준 |
|---|---|
| 즉시 (7일 이내, 발견 즉시) | 위험도가 높고 타 서비스 영향이 없는 경우 |
| 단기 (3개월 이내) | 적용 시 서비스에 영향을 미치는 경우 |
| 중기 (6개월 이내) | 영향도 파악에 오래 걸리는 경우 |
| 장기 (1년 이상) | 예산 수립이 필요한 경우 |
| 미조치 (위험 수용) | 영향도 파악이 불가하거나 위험 수용이 투입 비용보다 적은 경우 |

## 절차

1. 정보 보호 정책(관리적) 취약점의 처리 방안을 낸다. (p.67)
2. 기술 분야별 처리 방안을 낸다. (p.68) 서버(<표 3-3>), 네트워크(<표 3-4>: enable·VTY 비밀번호, 콘솔·VTY·AUX
   접근, 불필요 포트 차단), 애플리케이션(<표 3-5>: 관리자 페이지 분리, 추측 어려운 경로), DB(<표 3-6>: 불필요한 권한 회수,
   원격 OS 인증 제한).
3. 허용 위험 수준을 정하고 조치 계획을 만든다. (p.70) 취약점마다 처리 유형, 조치 기간, 판단 근거.
4. 분야별 위험 처리 계획을 세운다. (p.72, <표 3-8>~<표 3-11>)
