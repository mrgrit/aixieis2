# 시스템별 보안로그 분석 (학습 2-1)

목표: 선별된 보안시스템에서 발생한 보안로그를 분석한다.

## 절차

1. **공격 여부 판정 기준을 조사하고 판별한다.** (p.34)
   - 보안관제 담당 부서·업무 매뉴얼에서 사이버공격 판정 기준을 찾는다. 랩: `policy_docs`.
   - 징후를 제시한 담당자(누가, 언제, 무엇을 봤는지)를 확인한다.
   - 기준에 따라 징후가 공격인지 판별한다.
2. **분석에 쓸 보안시스템을 선별한다.** (p.38)
   - 조직의 전체 시스템을 확인하고(랩: `asset_inventory`, `network_topology`), 그중 보안시스템을 고른다.
3. **공격을 탐지한 보안시스템을 선별한다.** (p.40)
   - 사고 발생 내역에서 보안이벤트를 탐지한 시스템을 확인하고, 네트워크 구성도에 표시(marking)한다.
   - 징후와 관련 없는 시스템은 고르지 않는다. 예: '웹 서버 속도 저하 + 비정상 로그인'
     징후에는 문서보안(DRM)보다 IPS(네트워크 공격·무차별 대입)와 WAF(웹 애플리케이션 공격)가 먼저다.
4. **선별한 시스템의 분석 방법을 익힌다.** (p.41) 운영 매뉴얼의 로그 분석 방법을 확인한다.
5. **그 방법대로 분석하고 정리한다.** (p.42) 시스템마다 분석 내용을 따로 정리한다.

## 선별 사유를 쓰는 법

| 선별 시스템 | 선별 사유(공격 경로·피해 파악 관점) | 필수 검색 조건 |
|---|---|---|
| 예) 방화벽 | 공격 IP가 경계를 통과했는지, 허용·차단 이력 | 출발지 IP, 목적지 IP·포트, 시간 범위 |
| 예) 웹 서버 | 요청이 서버까지 도달해 처리됐는지 | 출발지 IP, URL, 응답 코드, 시간 범위 |

## 유의 (p.42 tip)

분석 범위와 수준은 분석자의 지식·경험에 따라 달라진다. 그래서 고른 시스템과 고른 이유, 검색 조건을 반드시 남겨 다른 분석가가 재현할 수 있게 한다.
