# SW개발 보안요구사항 명세와 설계 (학습 1-1)

목표: 명세된 보안요구사항을 만족하는 응용프로그램을 설계한다.

## 용어 (필요 지식)

- **SW개발 보안**: 개발 단계부터 보안약점을 제거해 안전한 SW를 구축하는 활동이다(p.3).
- **보안약점과 취약점** (<표 1-2>, p.4)

  | 구분 | 보안약점(weakness) | 취약점(vulnerability) |
  |---|---|---|
  | 발생 단계 | 개발 단계(정적 오류) | 운영 단계(동적 오류) |
  | 성격 | 공격에 활용될 여지가 있는 오류 | 실제로 공격 구현이 가능한 오류 |
  | 분류 체계 | CWE | CVE |

- **SDLC 단계별 보안 활동과 산출물** (<표 1-3>, p.5): 요구사항 분석(보안요구사항 정의서, 보안적용계획서) →
  설계(보안 프레임워크) → 구현(시큐어 코딩, 보안약점 진단 결과서·조치 결과) → 테스트(테스트 결과서, 결함 보고서,
  취약점 조치 결과서) → 운영·유지보수(보안 패치 결과서, 진단·조치 결과서).

## 절차

1. **내·외부 환경 분석으로 보안 항목을 식별한다.** (p.12) 보안 관련 법규와, 해당 IT 기술에 특정한 규정이 있는지
   조사한다(<표 1-8> SW개발 보안 관련 규정·지침, p.13). 랩: `policy_docs`.
2. **SW개발 보안 가이드의 보안 설계 기준을 확인한다.** (p.15) 행정기관 및 공공기관 정보시스템 구축·운영 지침의
   개발 보안 규정(<표 1-9>)과 설계 단계 보안 설계 기준(<표 1-10>)을 확인한다(p.16).
   적용 범위: 신규 개발은 설계 단계 산출물과 소스코드 전체, 유지관리는 변경된 설계 산출물과 소스코드 전체(p.16).
3. **정보의 자산 가치에 따라 중요 정보를 식별한다.** (p.16) 랩: `asset_inventory`의 중요도.
4. **개발 환경의 계획과 통제 정보를 식별한다.** (p.17) PM이 보안요구사항을 분석해 수행 계획을 세우고,
   보안 환경의 적용 기술(이행 방안, 참조 기술 목록, 적용 가능성)을 검토한다.
5. **보안적용계획서와 점검표를 작성한다.** (p.18, <표 1-11> 설계 단계 SW 보안적용계획서 점검표 사례, p.19)

## 산출물

| 요구사항 ID | 보안 항목(<표 1-10> 기준) | 요구사항 | 설계 반영 위치 | 검증 방법 |
|---|---|---|---|---|

예) SR-01 입력데이터 검증 및 표현 — 로그인·검색 입력은 서버에서 검증하고 SQL은 바인딩으로만 실행한다 —
검증: 보안약점 진단 도구 결과와 인젝션 시험.
