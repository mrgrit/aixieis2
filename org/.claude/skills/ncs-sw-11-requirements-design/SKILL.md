# SW개발 보안요구사항 명세와 설계 (학습 1-1)

## 절차

1. **내·외부 환경 분석으로 보안 항목을 식별한다.** (p.12) 보안 관련 법규, 해당 기술에 특정한 규정이 있는지
   조사한다(<표 1-8>). `policy_docs`.
2. **SW개발 보안 가이드의 설계 기준을 확인한다.** (p.14) 행정·공공기관 정보시스템 구축·운영 지침의 개발 보안
   규정(<표 1-9>). 진단 대상: 신규 개발은 설계 산출물과 소스코드 전체, 유지관리는 변경된 산출물과 소스코드 전체(p.15).
   설계 단계 보안 설계 기준(<표 1-10>)으로 요구사항을 만든다(예: SR-01 입력데이터 검증 및 표현).
3. **자산 가치에 따라 중요 정보를 식별한다.** (p.15)
4. **개발 환경의 계획과 통제를 식별한다.** (p.16) PM이 보안요구사항을 분석해 수행 계획을 세운다.
5. **보안 환경 적용 기술을 검토한다.** (p.16) 이행 방안, 참조 기술 목록, 적용 가능성.
6. **보안 적용 계획서와 점검표를 작성한다.** (p.17, <표 1-11>)
