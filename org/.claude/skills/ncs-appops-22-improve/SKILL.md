# 운영 개선 (학습 2-2)

## 절차

1. **개선 방안을 점검한다.** (p.25) 모든 취약점에 개선이 적용됐는지, 적용 후 취약점이 사라졌는지,
   확인 방법이 적절한지 본다. 같은 점검 방법(2-1)으로 다시 시험한다.
2. **아키텍처를 점검한다.** (p.25)
   - 외부망과 내부망이 분리돼 있는가 (랩: `network_topology` — int 존은 WAF를 거쳐야만 닿는다).
   - 서버 접근이 게이트웨이를 거치도록 제한돼 있는가.
   - 접근 통제, DB 암호화, 전송 구간 암호화가 적용돼 있는가.
   - 관리 계정 비밀번호가 암호화돼 관리되는가(하드코딩된 비밀번호가 없는가, <표 2-8>).
3. **정기 점검 계획을 세운다.** (p.26) 2-1의 체크리스트로 정기 점검표를 만들고, 점검 범위·담당·주기를
   정하고, 최신 동향과 패치 여부를 주기적으로 확인한다(<표 2-9>).

## 정기 점검 항목 예

WAF·IPS 탐지 규칙(시그니처) 최신 여부, 솔루션 패치 버전, 정책 예외 목록 적정성, 로그 수집·SIEM 연동
상태, 관리자 계정·접근 통제, 백업 상태.
