# 취약점 진단 수행 (학습 2-2)

## 면담 (pp.51-52)

준비: 대상자·일정 확정, 질문서 작성(<표 2-11>). 실시: 질문은 짧고 명확하게, 체크리스트 활용, 분야별 균등,
**답변의 책임 소재를 명확히**. 면담 답변도 근거로 기록한다.

## 기술적 진단과 양호·취약 판정 (pp.52-58)

| 대상 | 항목 | 양호 | 취약 |
|---|---|---|---|
| 서버 | root 원격 접속 제한 | `PermitRootLogin no` | `PermitRootLogin yes` — root로 원격 무차별 대입이 가능 |
| 서버 | 비밀번호 복잡성 | 정책에 맞는 복잡도 설정 | 미설정 |
| 서버 | 계정 잠금 임계값 | 일정 횟수 실패 시 잠금 | 최대 실패 0(제한 없음) — 무제한 대입 가능 |
| 서버 | 익명 FTP | 비활성 | 활성 |
| 서버 | Finger | `/etc/xinetd.d/finger`에 `disable = yes` | `disable = no` — 계정 정보 노출 |
| 서버 | NFS | 불필요 시 중지, 공유 제한 | 무제한 공유 |
| 네트워크 | Ping·포트 스캔·SNMP·배너 | 불필요 포트 닫힘, SNMP 기본 커뮤니티 변경 | 비인가 포트·기본 커뮤니티 |
| 애플리케이션 | 버퍼 오버플로, 포맷스트링, 평문 저장, 초기화 안 된 변수 | 없음 | 존재 |
| DBMS | 기본 계정·비밀번호 정책·원격 접속·시스템 테이블 권한·감사 기록·패치 | 정책 준수 | 미준수 |

## 결과 분석 (p.58)

1. 정보 보호 대책(관리적) 분석: 예) 정책을 만들었으나 공표·배포하지 않음 → '정책의 공표' 미이행.
2. 기술적 분석: 분야별 결과 → 세부 항목별 결과(<표 2-13>, <표 2-14>).
3. 종합 의견: 관리적·기술적 결과를 합쳐 가장 시급한 개선 방향을 한 문장으로 쓴다.

| 구분 | 진단 항목 | 분석 요약 | 이행 여부 |
|---|---|---|---|
