# SW개발 보안 구현 (학습 2-1)

## 구현 (pp.50-52)

1. 기능 명세서에 따라 기본 설계서를 쓰고 상세 설계에 반영한다. 보안 담당·평가자가 설계대로 구현됐는지 소스코드를 확인한다.
2. 구현 환경을 관리한다: 로그인 관리, 패스워드 관리(안전한 암호화 알고리즘, <표 2-9>), 데이터 보안 관리.

## 정적 분석 (p.53)

XSS, 인젝션, 불안전한 직접 객체 참조, 불안전한 암호 저장, URL 접근 제한 실패, 취약한 인증·세션 관리, CSRF,
잘못된 보안 설정, 불충분한 전송 계층 보호, 검증되지 않은 리디렉트·포워드, 애플리케이션 로직 결함, 인증 우회,
권한 부여 우회를 점검한다.

## 보안약점 진단 (pp.56-60)

1. **도구를 준비한다.** 보안인증(CC) 제품, 기관 진단 요청, 또는 공개 SW 점검 도구.
2. **진단한다.** 대상 범위를 식별하고(신규 개발: 설계 산출물과 소스 전체 / 유지관리: 변경분 전체) 도구로 진단한다.
   랩: `code_read`, `sast_results`.
3. **오탐을 예외 처리한다.** 도구는 룰셋(패턴) 기반 텍스트 분석이라 오진단이 있다. 개발자와 **동료 검토**로
   검출 항목을 분석하고, 오탐이면 도구의 방법대로 예외 처리한다. 예외마다 사유를 적는다.
4. **조치한다.** 예) SQL 인젝션: 문자열 결합 대신 바인딩(Prepared Statement) 사용(<표 2-12>).
   조치는 `change_prepare`(kind=code)로 수정 diff와 재진단 계획을 올린다.
5. **난독화 필요성을 검토하고 필요하면 적용한다.** (p.60)
