# 운영 개선 방안 수립 (학습 2-1)

## 절차

1. **현황을 파악한다.** (p.25) 분석 대상을 정하고 자료(구성도, 정책, 로그)를 확보한다.
2. **점검 대상을 고른다.** (p.25) 중요도·위협 가능성이 높은 솔루션, 우선순위 높은 요구사항으로
   도입된 솔루션부터. 체크리스트(<표 2-3>)를 작성한다.

   | 구분 | 점검 항목 |
   |---|---|
   | 솔루션 SW/HW 관리 | 인증 여부, 최신 패치, 불필요한 서비스 제거 |
   | 계정 관리 | 기본 비밀번호 변경, 관리자 비밀번호 주기적 변경 |
   | 원격 관리 | 관리자 원격 접근 통제, 유휴 시 접속 종료 |
   | 정책 관리 | 정책 중복 점검, 정책 변경 통제 절차 |

3. **진단한다.** (p.25) 네트워크 진단(원격 접속, 침입 흔적)과 모의 해킹 진단으로 나눈다.
4. **결과를 분석한다.** (p.26) 도구 결과와 수동 점검 결과를 따로 분석한다.
5. **보고서와 보안 대책을 낸다.** (p.27) 보안 목표·체계를 세우고 단계별 대책을 정한다.

## 문제 → 왜 문제인가 → 개선

| 문제 | 왜 문제인가 | 개선 방안 |
|---|---|---|
| 방화벽 중복 규칙·우선순위 오류 | 처음 일치 규칙이 적용되므로 아래 규칙이 무력화되거나 정상 트래픽이 차단된다 | 정책 재정비(중복 제거, 구체적 규칙을 위로) |
| IDS 탐지 정책 미업데이트 | 새 공격 패턴을 탐지하지 못한다(미탐) | 탐지 정책 최신화와 정기 업데이트 |
| 신규 대역 미반영 | 주소 그룹이 실제와 달라 과도 허용이 남는다 | IP 주소·자산 정보 현행화 |
| 정책 변경 이력 누락 | 누가 왜 바꿨는지 추적할 수 없어 사고 원인 분석과 감사가 불가능하다 | 변경 이력 관리 절차 수립 |
| 방화벽·IDS 로그 상관분석 미적용 | 공격 흐름을 한 번에 볼 수 없다 | 연동·상관분석 활성화(관제와 협업) |

## 산출물

개선 과제 목록(문제, 근거, 영향, 개선안, 우선순위, 담당), 그리고 개선안마다 **검증 방법**(무엇을 보면 개선됐다고 할 수 있나).
