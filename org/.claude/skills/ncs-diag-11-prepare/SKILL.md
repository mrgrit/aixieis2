# 진단 준비 및 취약점 정보 파악 (학습 1-1)

## 절차

1. **조직의 미션·전략을 파악한다.** (p.7) 경영 전략 → IT 전략 → 보안 목표 순서로 연결한다. 이 연결이 자산
   중요도의 근거가 된다(예: '비대면 채널 강화'가 전략이면 대고객 웹 서버의 가용성 중요도가 올라간다).
2. **자산 정보를 수집한다.** (p.9) `asset_inventory`, `network_topology`.
3. **자산 유형을 작성하고 장비 현황을 파악한다.** (pp.9-10)
4. **자산별 중요도를 산정한다.** (p.10) 중요도 점수 체계 → 점수 기준 → 자산별 산정(<표 1-6>~<표 1-8>).
5. **대상별 취약점 정보를 파악한다.** 유닉스 서버 예: 계정 관리, 서비스 관리, 파일 시스템(<표 1-9>).
6. **위협 시나리오를 쓰고 발생 빈도와 피해 규모를 산정한다.** (p.12)

   | 평가 | 피해 규모 | 발생 빈도 (<표 1-10>) |
   |---|---|---|
   | 낮음 | 손실이 매우 경미 | 자산 생명 주기 동안 거의 발생 안 함 |
   | 중간 | 손실이 있으나 업무에 중대한 영향 없음 | 두세 차례 |
   | 높음 | 손실이 크나 업무 중단은 없음 | 다섯 번 이상 |
   | 매우 높음 | 손실이 매우 크고 업무 중단 있음 | 매우 자주 |

## 자산 관리 대장

| 자산 유형 | 자산명 | 용도 | 망 위치 | OS·모델 | 중요도(상·중·하) | 비고 |
|---|---|---|---|---|---|---|

## 자산 유형별 핵심 점검 항목

- Unix·Linux 서버: 계정 관리(root 원격 접속, 비밀번호 정책, 잠금 임계값) / 서비스 관리(불필요 서비스,
  Finger·익명 FTP·NFS) / 파일 시스템(passwd·shadow 권한, SUID).
- 네트워크·보안 장비: 계정 관리(기본 계정·비밀번호) / 접근 관리(관리 접속 허용 IP, VTY) / 패치 관리(OS 버전).
