# SW개발 보안 환경 구축 일정 계획 수립 (학습 1-2)

## 취약점 점검 환경 (pp.24-27)

입력물(점검 계획서, 점검 케이스 설계 명세서) → 도구·기법(환경 정보 수집) → 계획서·설계·케이스·절차 명세서 검토,
점검 목록 분석, 가정 분석, 도식화 → 산출물(<표 1-14>).

## 구현 계획 (pp.28-32)

1. 조직의 개발 업무 현황을 모아 보안 등급으로 나눈다(<표 1-15>).
2. SW 보안약점 유형을 파악한다.

   | 유형 | 뜻 |
   |---|---|
   | 입력데이터 검증 및 표현 | 입력값 검증 누락·부적절로 생기는 약점(SQL 삽입, XSS, 경로 조작 등) |
   | 보안 기능 | 인증·접근제어·암호화·권한 관리를 부적절하게 구현 |
   | 시간 및 상태 | 동시·병렬 처리에서 시간·상태 관리 부적절 |
   | 에러처리 | 에러 메시지에 중요 정보(시스템 정보, 상세 에러)가 포함되는 등 |
   | 코드 오류 | 타입 변환 오류, 자원 해제 누락 등 코딩 실수 |
   | 캡슐화 | 은닉이 필요한 데이터·기능을 충분히 캡슐화하지 않음 |
   | API 오용 | 의도와 다르게 API를 사용하거나 보안에 취약한 API 사용 |

3. 개발 환경과 구현 계획을 세운다. 소스코드 품질·개발 보안 점검 도구를 고른다(<표 1-16>, 공개 SW 도구).
4. 조직 보안 정책을 검토하고 등급·정책에 맞춘 보안 계획서를 쓴다(<표 1-17>~<표 1-19>).
