# SAST 결과 LLM 판정 (확장)

NCS 2-1은 오탐을 '동료 검토'로 걸러 예외 처리하라고 한다. IRIS 연구는 정적 분석(CodeQL)이 찾은 소스→싱크
경로마다 LLM에게 CWE 설명과 경로 위 코드 조각을 주고 판정하게 해서, 같은 벤치마크에서 탐지 수를 늘리고
오탐 비율을 낮췄다. 다만 최고 구성도 오탐 비율이 여전히 높았다. 그래서 이 판정은 **동료 검토를 대신하지 않고
앞단에서 줄 세우는 용도**로 쓴다.

## 절차

1. `sast_results`에서 검출 항목을 읽는다. 항목마다 약점 유형(CWE), 소스(입력 지점), 싱크(위험 함수), 경로를 확인한다.
2. `code_read`로 소스·싱크와 그 사이 코드를 읽는다(전체 파일이 아니라 경로 위 함수 중심).
3. 판정한다: 입력이 검증·인코딩·바인딩 없이 싱크에 닿는가. 이유를 먼저 쓰고 판정(정탐·오탐·판단 불가)을 쓴다.
4. 오탐이면 원인을 표시한다: **소스가 실제로 외부 입력이 아님** 또는 **싱크가 실제로 위험하지 않음(예: 이미 바인딩)**.
   같은 소스·싱크를 공유하는 다른 경로도 같은 원인인지 한 번에 확인한다.
5. 결과를 동료 검토 대상 목록으로 넘긴다: 정탐 → 조치, 판단 불가 → 사람 검토, 오탐 → 예외 사유와 함께 검토.
