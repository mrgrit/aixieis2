# 업데이트 적용 (학습 4-2)

## 백업 (p.73)

패치 종류·대상, 영향 범위, 자산 중요도에 따라 백업 형태·범위를 고른다.

| 형태 | 내용 |
|---|---|
| 특정 파일 및 폴더 백업 | 특정 파일·폴더를 별도 저장 장치에 백업 |
| 전체 시스템 초기 백업 | 솔루션이 설치된 장비의 출하 시 이미지 전체를 백업 |
| 시스템 변경 사항 백업 | 변경 사항을 스냅샷 형태로 저장해 복구 지점 생성 |

주의: 이 세 형태는 학습모듈의 분류다. 흔히 말하는 전체·증분·차등 백업과 다르다.

주기는 대상 유형에 따라 정기적으로 할지, 큰 변경 직전에 할지 정한다. 계획대로 백업을 수행한다
(`backup_status`로 확인).

## 복구 계획 (p.74)

패치 시험에서 서비스에 악영향이 있으면 복구하도록 계획하고, 백업 형태·대상별 복구 매뉴얼을 미리 쓴다
(<표 4-2> 웹 서버 장애 시 복구 매뉴얼 예시).

## 적용 후 (p.74)

1. 패치 결과를 업무 담당자에게 통보한다.
2. 장애가 나면 복구 조치를 수행한다.
3. 서비스 정상 여부를 모니터링하고 확인 결과를 보고한다.
