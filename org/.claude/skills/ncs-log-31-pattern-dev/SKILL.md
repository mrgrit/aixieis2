# 탐지패턴 개발 (학습 3-1)

목표: 공격에 사용된 공격도구와 탐지로그를 통해 관련 탐지패턴을 개발한다.

## 절차

1. **조직의 전체 보안시스템을 조사한다.** (p.65) 관리 부서·실무자를 통해 정보시스템 목록을 받고
   보안시스템을 추린다. 랩: `asset_inventory`, `worker_directory`.
2. **공격별 대응 기능을 가진 시스템을 식별한다.** (p.66) 시스템별 보안 기능 → '탐지' 기능이
   있는 시스템 → 그중 '사용자 탐지패턴' 기능을 제공하는 시스템. 랩: IPS(`ids_rules`).
3. **공격도구를 조사해 공격 방식을 분석한다.** (p.68) 침해대응 담당(`cert-coordinator`)에게
   공격도구 분석 결과를 요청한다(`handoff_request`). 없으면 로그에서 확인되는 범위만 쓴다.
4. **탐지로그의 기본정보를 확인한다.** (p.68) 출발지·목적지 IP와 포트, 프로토콜, 페이로드의 특징 문자열.
5. **탐지패턴을 개발한다.** (p.71) 적용할 시스템을 정하고, 그 시스템 설명서의 **패턴 표현식**을
   확인한 뒤(예: Suricata 규칙 문법), 기본정보를 표현식으로 옮긴다.

## 패턴 작성 원칙

- 특정 IP 하나에만 거는 패턴은 그 IP가 바뀌면 쓸모가 없다. 공격 방식의 특징(페이로드, 순서,
  빈도)을 잡고, IP는 필요할 때만 조건에 넣는다.
- 정상 트래픽에도 나오는 문자열만으로 패턴을 만들지 않는다. 오탐 가능성을 함께 적는다.
- 패턴마다: 목적, 표현식, 적용 시스템, 예상 오탐, 근거 로그.

## 넘길 일

작성한 패턴의 적용은 `nw-sec-ops`(IPS) 또는 `app-sec-ops`(WAF)에 `handoff_request`로 넘긴다.
적용 뒤 성능 평가는 `ncs-log-32-pattern-tuning`.
