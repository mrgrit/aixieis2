# 업데이트 계획 수립 (학습 4-1)

## 패치 관리 절차 (p.46, [그림 4-2])

신규 업데이트 정보 수집 → 보호 대상 목록 → 솔루션 목록·벤더 패치 방법 정리 → 최신 취약성·패치 확인
→ 적용 환경 분석 → 적용 계획 → 패치 테스트 → 적용 → 이상 현상 모니터링.

## 계획서에 반드시 넣을 것 (pp.51-52)

1. 모의 테스트 일정(정기 점검 시간 고려), 업데이트 일정, 작업자, **복구 계획**, **비상 연락망**(사전 통지).
2. 서비스 중단이 있으면 반드시 사전 공지.
3. 관련 부서·담당자와 계획서를 공유·협의하고 보완.
4. 보안 책임자와 정보 서비스 책임자의 승인을 받아 확정(랩: `approval_request` → `ciso`).

과거에 업데이트 후 장애가 난 이력이 있으면, 그 원인을 계획서의 위험 항목에 적고 모의 테스트에서 같은 조건을 재현한다.
