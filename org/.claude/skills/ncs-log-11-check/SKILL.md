# 보안로그 확인 (학습 1-1)

목표: 사이버공격 발생 시 침해대응 절차에 따라 장비별로 발생한 보안로그를 확인한다.

## 절차

1. **사이버공격 발생 내역을 확인한다.** (p.7)
   - 누가 인지했는지(탐지 담당) 확인하고, 발생 시간·공격 유형·공격 종류·탐지 장비를 정리한다.
   - 랩: 요청 내용과 `siem_search`로 경보를 확인한다.

   | 항목 | 내용 |
   |---|---|
   | 공격 발생 시간 | |
   | 공격 유형 / 종류 | 예) DDoS / TCP-Syn Flooding |
   | 공격 탐지 정보시스템 | 예) IPS |

2. **침해대응 절차를 확인한다.** (p.8)
   - 보안 관리 조직과 책임자, 침해대응 절차가 등록된 문서, 이해관계자, 주의사항을 확인한다.
   - 랩: `policy_docs`(침해대응 절차), `worker_directory`(조직·담당). 절차 문서가 없으면 그 사실을 '한계'에 적는다.

3. **침해사고 유무를 확인할 수 있는 보안장비를 확인한다.** (p.9)
   - 전사 보안장비 목록을 확인하고, 이번 탐지에 실제로 쓰인 장비를 고른다.
   - 랩: `asset_inventory`, `network_topology`.

4. **보안장비에서 보안로그를 확인한다.** (p.10)
   - 장비의 관리자 설명서에서 로그 확인 방법을 찾고, 그 방법대로 로그를 조회한다.
   - 랩: 장비별 `log_read`(fw, ips, waf, web, host, auth). 조회 결과는 세 가지로 적는다.
     수집됨 / 일부 누락(`partial`) / 확인 불가(`no_data`). 확인 불가는 '이벤트 없음'이 아니다.

## 산출물

- 발생 내역 표(위), 확인한 침해대응 절차 요약, 장비별 로그 확보 표.

| 장비 | 상태 | 건수 | 조회 기간 | 메모 |
|---|---|---|---|---|

## 유의 (p.7, p.13)

- 분석 전에 조직의 정보시스템 종류·네트워크 구성·장비 운영 목적을 알고 있어야 한다.
- 장비 접속 계정과 권한은 미리 확보돼 있어야 한다. 권한이 없으면 직접 우회하지 말고 담당에게 요청한다.
