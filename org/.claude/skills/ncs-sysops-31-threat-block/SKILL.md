# 시스템 보안 위협 식별 및 차단 (학습 3-1)

## 절차

1. **솔루션과 보호 자산을 파악한다.** (p.48) 구축 현황 대장 등 산출물로 설치 현황을, 아키텍처 산출물로
   보호 자산을, 업무 담당 인터뷰로 자산 우선순위를 조사한다.
2. **솔루션별 취약점과 위협을 분석한다.** (p.49)
   1. **보안 솔루션**을 분해해 구성 요소를 도출한다.
   2. 구성 요소를 기반으로 **위협 타깃**(threat target)을 도출한다.
   3. 위협 요소별 **취약점 진단 항목**을 도출하고 위협 타깃별 위협을 도출한다.
   4. 발견된 위협에 **개선 방안**을 수립한다.
3. **대응 조치가 가능하면 수행한다.** (p.49) 장비 설정 취약점 제거, 솔루션 정책 변경, 최신 업데이트·패치,
   보안 스캐너 점검, 취약점 조치. 불필요한 데몬 서비스는 삭제를 권고한다(<표 3-1>).
4. **대응이 불가능하면 긴급 조치를 한다.** (p.50) 해당 취약성 집중 모니터링, 취약한 서비스 중단, 더 강력한
   솔루션 도입·추가, 정책 강화.

## 증거 먼저

조치 전에 현재 상태(계정, 예약 작업, 프로세스, 설정 파일)를 조회해 근거로 남긴다. 지속성 흔적(무단 계정,
cron, SSH 키, ld.so.preload, setuid 사본)을 지우기 전에 원본 위치와 시각을 기록하고, 사고 조사가 필요하면
`cert-coordinator`에 넘긴다.
