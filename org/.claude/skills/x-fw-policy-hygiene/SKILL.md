# 방화벽 정책 위생 점검 (확장)

NCS 2-1은 '정책 중복 점검'을 체크리스트 한 줄로 둔다. 규칙이 많아지면 눈으로는 못 찾는다. 처음 일치 규칙이
적용된다는 성질을 써서, 규칙 쌍마다 관계를 분류한다.

## 관계 분류

| 관계 | 정의 | 영향 |
|---|---|---|
| 가림(shadowing) | 위 규칙이 아래 규칙의 범위를 모두 덮고 동작이 다르다 | 아래 규칙은 절대 적용되지 않는다(의도한 허용·차단 실패) |
| 중복(redundancy) | 위 규칙이 아래 규칙을 덮고 동작이 같다 | 아래 규칙은 불필요(정리 대상) |
| 일반화 | 아래 규칙이 위 규칙을 덮고 동작이 다르다 | 의도된 예외일 수 있음, 확인 필요 |
| 상관 | 범위가 일부만 겹치고 동작이 다르다 | 순서에 따라 결과가 달라짐, 위험 |
| 과다 허용 | Any 출발지·목적지·넓은 포트 범위 허용 | 최소 허용 위반 |
| 미사용·만료 | 일정 기간 적중 0, 기한 지난 임시 허용 | 정리 대상 |

## 절차

1. `fw_rules`로 규칙을 순서대로 읽고 각 규칙의 5요소(출발지·목적지·프로토콜·포트·동작)를 표로 만든다.
2. 규칙 쌍마다 위 관계를 판정한다. 판정마다 두 규칙 번호를 근거로 적는다.
3. 적중 수(로그)가 있으면 미사용 규칙을 찾는다(`log_read` fw).
4. 정리안: 가림·상관은 순서 조정이나 범위 수정, 중복·미사용·만료는 삭제 후보, 과다 허용은 범위 축소.
5. 정리안은 `x-change-verify`로 전후 연결 시험표를 만든 뒤 `change_prepare`로 올린다.
